# Персональные учётные записи и полномочия

Реализованы роли admin, operator и auditor, персональный вход в веб-интерфейс и CLI по mTLS-сертификату роли user. Управление учётными записями доступно администратору через кнопку «Пользователи» и API /v1/users. Текущая идентичность доступна через /v1/me.

## Администратору

Администратор имеет полный доступ. Аудитор читает разрешённые данные и не может изменять конфигурацию или запускать операции. Оператор получает права отдельно: run, verify, cancel, restore, erase, cleanup. Без явного разрешения операция запрещена. Создание заданий, настройка репликации, расписаний проверок, сроков хранения, удержания и выдача кодов Rescue остаются административными действиями.

Области заданий и площадок пересекаются: пользователь видит задание только при совпадении обеих областей. Флаг all_jobs снимает ограничение по заданиям, all_sites — по площадкам. Площадка источника определяется политикой защиты 3-2-1. При отсутствии такой политики доступ пользователя с ограничением по площадкам закрыт. Пустые списки при выключенных флагах означают отсутствие доступа, а не полный доступ.

Ограниченная учётная запись может читать свои задания, операции, журналы операций и отчёты, запускать резервирование и проверку целостности при наличии соответствующих прав. Инвентаризация общих хранилищ и карточки защиты выдаются в отфильтрованном виде (см. ниже). Метрики компонентов, общий аудит и политики Kubernetes/WAL ей не выдаются. История и отчёты фильтруются SQL-запросом до применения пагинации.

Восстановление требует разрешения restore, доступа к исходному заданию и отдельно к целевой площадке через restore_site_ids/all_restore_sites. Оператор выбирает утверждённый restore_target_id. Отмена, очистка и операции с общими носителями по-прежнему требуют глобальной исходной области и отдельного разрешения. Общий инвентарь смешанных репозиториев остаётся закрыт для ограниченных пользователей. Подробности: [целевые площадки и сертификаты](recovery-access-and-certificates.md).

Пароль содержит от 16 до 72 байт; в каталоге сохраняется bcrypt-хеш в отдельной колонке, API его не возвращает. Логин: до 64 символов, латинские буквы, цифры, дефис и подчёркивание; первый символ — буква или цифра. Изменение учётной записи увеличивает version. Сохранение устаревшей версии возвращает 409.

Любое изменение учётной записи отзывает её текущие веб-сессии. Сессия действует максимум 8 часов и использует Secure, HttpOnly, SameSite=Strict cookie. При изменении пароля поле не должно быть пустым; пустое поле при редактировании сохраняет прежний пароль. Отключение disabled блокирует веб-вход и персональный CLI. Уже запущенные задания продолжаются; при необходимости их отменяет уполномоченный оператор.

Вход с пустым логином или bootstrap использует существующий password_file менеджера и сохраняет административный доступ для восстановления доступа. Сертификаты ролей admin и auditor сохраняют прежние глобальные полномочия; для персональных ограничений выдавайте сертификаты роли user, а не admin. Доступ к CA, bootstrap-паролю и административным сертификатам должен оставаться у администраторов.

## CLI

Получить идентичность и список пользователей:

```sh
bin/srk --config .local/admin.json manager me
bin/srk --config .local/admin.json manager users list
bin/srk --config .local/admin.json manager users put --file /secure/account.json
```

Файл account.json содержит поля username, name, role, version, disabled, all_jobs, all_sites, job_ids, site_ids, permissions и необязательное password. При создании version равен 0 и пароль обязателен. При изменении используйте актуальную version из users list. Храните файл с паролем с правами 0600. Пароль не передаётся аргументом командной строки и не включается в результат команды.

Персональный сертификат выпускается существующей командой pki issue с ролью user и ID, совпадающим с username. В клиентской конфигурации задаются role=user, id=username, installation, ca, cert, key и URL менеджера. Каждый запрос проверяет действующее состояние учётной записи в каталоге. Изменение роли/области применяется к следующему запросу без перевыпуска сертификата; отключение пользователя запрещает доступ. Штатный отзыв сертификата по серийному номеру остаётся доступен через pki revoke. Управляемый выпуск по CSR, ротация с перекрытием и отзыв доступны через веб-интерфейс и CLI; см. [инструкцию](recovery-access-and-certificates.md).

## Оператору

Войдите под своим логином. Имя и роль отображаются в верхней панели. Работайте с доступными заданиями через историю, карточку операции и экспорт отчётов. Скрытые кнопки отражают основные ограничения; окончательное решение всегда принимает сервер. Ответ 403 означает недостаточные права; ответ 401 требует повторного входа. После изменения вашей учётной записи администратором войдите заново.

В журнале API-операций и отказов указывается роль/логин исполнителя. Изменения учётных записей фиксируются событиями access.user.update.requested и access.user.updated без паролей и хешей.

## Общие хранилища и карточки 3-2-1

Ограниченным операторам и аудиторам доступен раздел «Хранилища», карточки «Защита 3-2-1» и API `/v1/storage-view`. Сервер пересекает разрешённые задания с площадкой источника из политики защиты. Затем допускаются только копии на разрешённых площадках хранения. Неизвестные и несопоставленные копии не раскрываются. Синтетические задания репликации учитываются по исходному заданию; доступ к другой площадке автоматически не расширяется.

Дисковый инвентарь `/v1/media/{media}/snapshots` также фильтруется. Право определяется по каталогу менеджера, медиасерверу и идентификатору репозитория, а не только по полю job_id, полученному с носителя. Ответ содержит сведения разрешённых копий, логический размер и сроки; вложенные результаты операций, служебные связи репликации и общая статистика дедупликации исключены. Параметр verify для ограниченного пользователя не запускает проверку всего общего репозитория.

Копии на общих кассетах и flash доступны в карточках и сводном представлении. Полный каталог библиотеки, роботика, очереди, журналы и операции всего носителя остаются доступны только глобальной исходной области с соответствующими полномочиями. Ограниченный пользователь не получает общую ёмкость, занятое место, число блоков, общий аудит или метрики компонентов: эти значения могли бы раскрыть чужую активность.

Карточки явно отмечены как расчёт разрешённой области. Счётчики копий, RPO, удалённая копия и результаты восстановления рассчитываются только из доступных сведений. Нельзя трактовать отсутствие подтверждения как отсутствие копий во всей инфраструктуре. При ограничении площадок для подтверждения восстановления нужна явная разрешённая площадка в записи результата; старые записи без такой привязки не учитываются. Скрытая зависимость Longhorn не раскрывается и не подтверждает защищённость PVC. История для расчёта фильтруется до ограничения числа строк.

Настройки в ответе ограниченного пользователя — проекция для чтения: без чужих политик, целей восстановления и глобального счётчика версии. Сохранить её обратно нельзя. Администратор сохраняет полный доступ. Глобальный аудитор видит полный инвентарь, но не может изменять настройки или выполнять операции. Оператор выполняет только явно разрешённые операции; просмотр отфильтрованных копий не даёт разрешений на очистку общего носителя.

```sh
bin/srk --config personal.json --json manager storage-view
bin/srk --config personal.json --json manager protection report
bin/srk --config personal.json --json manager protection settings
bin/srk --config personal.json --json manager repository snapshots MEDIA_ID
```

CLI использует тот же API и персональный сертификат роли user. Прямой доступ такого сертификата к служебному API медиасервера запрещён. При изменении прав каждый следующий запрос проверяется заново. Интерфейс очищает показанные данные и диалоги при смене учётной записи или отзыве сессии; ответы от предыдущей сессии отбрасываются.
