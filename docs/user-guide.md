# Руководство пользователя GData SRK 0.9.2

## Доступ и начало работы

Получите у администратора HTTPS-адрес менеджера, доверенный сертификат CA,
персональный логин и пароль. Откройте адрес в браузере, настройте доверие
к выданному CA и войдите. Не обходите предупреждение о неизвестном или
неподходящем сертификате: проверьте адрес и CA у администратора.

Роль и имя показаны в верхней панели. Оператор видит разрешённые задания
и площадки; аудитор просматривает сведения и отчёты. Операции запуска,
проверки, восстановления и отмены требуют отдельных разрешений.
Создание заданий и управление пользователями выполняет администратор.
Отсутствие копии в вашей области видимости не доказывает её отсутствие
во всей системе. Подробнее: [права доступа](access-control.md).

## Резервное копирование

1. Откройте список заданий. Проверьте источник, агент, медиасервер и расписание.
2. Запустите доступное задание вручную либо дождитесь планового запуска.
3. В текущей активности и истории откройте операцию. Следите за этапом,
   прогрессом и журналом; принятый в очередь запуск ещё не означает успеха.
4. Дождитесь завершения. При ошибке сохраните ID операции и сообщение,
   устраните причину вместе с администратором и повторите запуск.
5. Проверьте копию штатной операцией проверки целостности. Для контроля
   пригодности регулярно выполняйте пробное восстановление.

Файловый агент читает живое дерево без общего снимка файловой системы.
Изменение читаемого файла может завершить операцию ошибкой. Для баз данных
используйте подготовленные администратором профили PostgreSQL/MySQL,
для ВМ — соответствующие интеграции. Не считайте файловую копию работающей
СУБД согласованной копией базы.

## Восстановление

1. В истории выберите успешную копию нужного задания и времени.
2. Выполните проверку целостности и изучите её результат.
3. Выберите разрешённую цель восстановления и **новый** каталог назначения.
   Путь должен входить в разрешённые корни агента; существующий каталог
   автоматически не перезаписывается.
4. Запустите восстановление, дождитесь результата и проверьте содержимое.
5. Для приложения выполните его собственную проверку. Перенос восстановленных
   данных в рабочую систему согласуйте с администратором приложения.

Для PostgreSQL PITR укажите время с часовым поясом. Успех означает достижение
цели и остановленный кластер в новом каталоге. Запуск и переключение приложения
выполняются отдельно. См. [WAL/PITR](wal-pitr.md).
Восстановление ВМ, Kubernetes, лент, flash и физического диска имеет отдельные
условия: используйте ссылки в конце инструкции и помощь администратора.

## CLI

Для персонального CLI получите конфигурацию с сертификатом роли `user`,
его закрытый ключ и CA. Храните закрытый ключ с правами 0600; не передавайте
его в issue. В примерах `personal.json` — выданная конфигурация, `JOB_ID`,
`RUN_ID`, `TARGET_ID` и пути нужно заменить. Глобальные флаги идут перед `manager`.

```sh
srk version
srk --config personal.json --json manager me
srk --config personal.json --json manager jobs list
srk --config personal.json --wait --timeout 30m manager jobs run JOB_ID
srk --config personal.json --json manager runs list
srk --config personal.json --json manager runs get RUN_ID
srk --config personal.json --wait --timeout 30m manager runs verify RUN_ID
srk --config personal.json --wait --timeout 2h manager runs restore RUN_ID \
  --restore-target TARGET_ID --destination /var/lib/srk/restores/recovery-001
srk --config personal.json manager runs cancel RUN_ID
srk --config personal.json manager report --format xlsx --out operations.xlsx
```

Без `--wait` код 0 подтверждает только принятие операции. Тайм-аут клиента
не отменяет серверное задание: проверьте историю, прежде чем повторять запуск.
Коды CLI: 0 — успех; 1 — ошибка операции; 2 — аргументы/конфигурация;
3 — отказ в доступе; 4 — недоступность или тайм-аут; 5 — конфликт состояния.

## Отчётность и типовые проблемы

Используйте фильтры истории по времени и состоянию, откройте журнал конкретной
операции. Экспорт CSV/XLSX содержит только разрешённую область данных.
Карточки 3-2-1 также рассчитаны в пределах вашей области доступа.

- 401: войдите заново; изменение учётной записи отзывает активные сессии.
- 403: запросите нужное разрешение и область/цель восстановления у администратора.
- Компонент недоступен: передайте администратору ID и время операции.
- Недостаточно места: очистку и удержание проверяет администратор; не удаляйте
  блоки из репозитория вручную.
- Ошибка проверки: не используйте копию для переключения рабочей системы,
  сохраните журнал и проверьте другую точку восстановления.

При обращении в поддержку укажите версию, ID операции, время с часовым поясом
и обезличенный журнал. По завершении работы выйдите из веб-интерфейса.
