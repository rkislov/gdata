# Съёмные Flash/USB/SSD/HDD-носители

Linux-медиасервер поддерживает предварительно смонтированный отдельный файловый том с UUID. Путь задаёт администратор в конфигурации, а не запрос API. Проверяются /dev/disk/by-uuid, тип block device, устройство смонтированного каталога и mountinfo. После проверки каталог удерживается открытым через /proc/self/fd: отключение тома не переключает запись на каталог корневой ФС. На других ОС backend сообщает о недоступности Linux-проверки; тестовый probe используется только в тестах.

```json
{"removable":[{"id":"USB01","uuid":"YOUR-FILESYSTEM-UUID","mount":"/mnt/srk-usb","capacity_bytes":536870912000}]}
```

Носитель монтируется средствами ОС. Команда маркировки требует точный ID носителя и причину, создаёт `.srk-removable/identity.json`. Неизвестный существующий каталог не перезаписывается. Внутри используется проверенный автономный формат копий ленточного контура (манифест, уникальные блоки, SHA-256, readback), но это реальный файловый том, не эмуляция устройства. Сроки хранения и удержание защищают от удаления. Запись между разными копиями автономна: потеря одной не удаляет общие блоки остальных.

Кэш каталога на медиасервере сохраняется после отключения. Интерфейс: Хранилища → Flash / USB. Поля ID копии и исходного запуска доступны в истории операций. Восстановление возвращает копию в дисковый репозиторий и регистрирует её с удержанием; дальнейшее восстановление выполняется штатным способом.

```sh
srk --config admin.json manager removable inventory MEDIA
srk --config admin.json --wait manager removable label MEDIA USB01 --label 'Offsite USB' --confirm-barcode USB01 --reason 'Первичная маркировка'
srk --config admin.json --wait manager removable write MEDIA USB01 --run BACKUP_RUN_ID --retention-days 30
srk --config admin.json --wait manager removable restore MEDIA USB01 --copy COPY_ID --agent AGENT_ID
srk --config admin.json --wait manager removable import MEDIA USB01
srk --config admin.json --wait manager removable release MEDIA USB01
srk --config admin.json --wait manager removable attach MEDIA USB01
```

Для release выполняется syncfs, затем сервис блокирует новые операции до attach. Это **не unmount**: перед физическим отключением требуется штатное извлечение ОС. Форматирование разделов не реализовано. Операция recycle удаляет только копии СРК после проверки сроков и удержания; произвольные файлы тома не затрагиваются. Заполнение файловой системы может завершить операцию ошибкой, даже если указанный лимит ёмкости не достигнут. После потери связи частичная копия не считается пригодной. Автоматического ожидания повторного подключения в очереди пока нет: неуспешную операцию нужно повторить после подключения.

API: GET /v1/media/{media}/removable; POST /v1/media/{media}/removable/{volume}/operations с полями TapeRequest. Изменения доступны через manager; внутренний media endpoint принимает только mTLS manager. Очередь, прогресс и события используют существующие API runs. Для CLI рекомендуются идентификаторы верхнего регистра (USB01).

Проверено на файловом стенде с подставной проверкой монтирования: запись/автономное восстановление, потеря подключения, кэш каталога, release/attach, чужой UUID и удержание по сроку. Linux amd64 собирается. Настоящее USB-устройство, внезапная потеря питания и аппаратное извлечение не тестировались. SCSI-интеграция 0.9.1 по-прежнему не завершена.
